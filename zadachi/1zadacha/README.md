# Практическое задание: Online Store Transactions

## Что происходит в задании

Это задание посвящено **SQL-транзакциям** в базе данных интернет-магазина. 
Транзакция — это набор операций с базой данных, которые выполняются как единое целое:
либо все операции успешны, либо ни одна не применяется (принцип **атомарности**).

### Схема базы данных

База состоит из 4 таблиц:

| Таблица | Описание |
|---------|----------|
| **Customers** | Клиенты магазина (ID, имя, фамилия, email) |
| **Products** | Товары (ID, название, цена) |
| **Orders** | Заказы (ID, клиент, дата, общая сумма) |
| **OrderItems** | Позиции заказа (ID, заказ, товар, количество, промежуточный итог) |

### Три сценария транзакций

#### Сценарий 1: Размещение заказа
Самая сложная транзакция. При оформлении заказа нужно:
1. Создать запись в `Orders`
2. Для каждого товара создать запись в `OrderItems` (цена × количество = промежуточный итог)
3. Обновить `TotalAmount` в `Orders` суммой всех промежуточных итогов

**Почему это должна быть транзакция:** Если после создания заказа произойдёт ошибка при добавлении позиций, в базе останется «висячий» заказ без товаров. Транзакция гарантирует, что либо всё создастся, либо ничего.

#### Сценарий 2: Обновление email клиента
Простая транзакция — обновляет email у клиента. Атомарность гарантирует, что:
- Email обновится полностью, а не частично
- Не возникнет конфликтов с UNIQUE-ограничением
- При ошибке всё откатится

#### Сценарий 3: Добавление продукта
Добавляет новый товар в каталог. Атомарность гарантирует, что продукт не окажется в базе в «полудобавленном» состоянии.

### Технологии решения

- **Python** + **sqlite3** — стандартная библиотека для работы с SQLite
- **Dockerfile** — контейнеризация сервиса
- **docker-compose.yml** — orchestration (SQLite работает как встроенная БД, данные хранятся в volume)

## Структура файлов


## Как запустить

### Без Docker (локально)
```bash
python transactions.py
```

### С Docker Compose
```bash
docker compose up --build
```
